R.L ENERGIE - Suivi de maintenance v24 (100 % hors ligne)

CONTENU
  index.html, style.css, sw.js, manifest.json, icônes, logo-data.js
  js/        : le code de l'app, découpé par rôle (core, config, data, state, ui, actions, reset, exports, boot)
  libs/      : générateurs PDF / Excel / Word (aucun accès internet requis)
  docs/      : étiquettes, couples de serrage
  tests/     : tests automatiques (facultatif, à supprimer avant de fabriquer l'APK si tu veux l'alléger)

MISE EN LIGNE (GitHub Pages)
  1. Déposer TOUS les fichiers/dossiers à la racine du dépôt (garder js/, libs/, docs/).
  2. Settings > Pages > Deploy from a branch > main / root.
  3. Ouvrir l'adresse une première fois AVEC internet (le service worker met tout en cache), puis l'app fonctionne sans Wi-Fi.

MISE À JOUR
  - Remplacer les fichiers, puis changer le numéro V en haut de sw.js (rl-v24 -> rl-v25...).
  - Rouvrir l'app une fois avec internet : la nouvelle version s'active au démarrage suivant.
  - Si tu ajoutes un fichier dans js/, l'ajouter aussi à la liste du sw.js ET à index.html.
  - Cette version : cache « rl-v24h » (v24 + mot de passe oublié ; EmailJS configuré dans js/config.js : service, template et Public Key renseignés ; l'écran « Mot de passe oublié » indique quel réglage serait vide).

APK (web2apk) : de préférence envoyer le ZIP/dossier complet plutôt que l'URL, pour que tout soit embarqué dans l'APK.

ADMIN : au départ le bouton "Admin" entre SANS mot de passe. Pour protéger : Gestion > Droits & accès > « Exiger un mot de passe » (on en choisit un). On peut le réautoriser sans mot de passe au même endroit. Mot de passe modifiable : Droits & accès > Changer le mot de passe.

DROITS (v22) : deux profils.
  - Utilisateur (technicien) : aucun mot de passe. Il ne peut faire que ce que l'administrateur a autorisé.
  - Administrateur : mot de passe, tous les droits, non modifiable.
  Gestion > Droits & accès (visible seulement en mode admin) : un interrupteur par droit (planifier, modifier une date,
  exporter, modifier / supprimer un rapport, clients, procédures, documents, sauvegarde, coordonnées, diagnostic)
  + 3 préréglages : Restreint / Standard / Tout autoriser. Les droits sont enregistrés sur la tablette et inclus dans la sauvegarde JSON
  (ils ne sont restaurés que par un administrateur). Le bouton Gestion n'apparaît chez l'utilisateur que s'il a au moins un droit de gestion.
  Le mot de passe est protégé par PBKDF2 (sel + 150 000 itérations) quand le navigateur le permet ; 5 erreurs = blocage 30 s (conservé même si on recharge la page).

SAUVEGARDE
  - Gestion > Sauvegarde complète : tout (photos comprises). Sauvegarde "Sans photos" : beaucoup plus légère.
  - À la restauration, les rapports déjà présents sur la tablette gardent leurs photos.
  - Gestion > Diagnostic affiche l'espace utilisé ; une alerte apparaît au démarrage au-delà de 80 %.

DONNÉES : les clients sont désormais stockés dans IndexedDB (comme les rapports). Au premier démarrage de la v21,
  les clients de la v19/v20 sont migrés automatiquement. Ne pas revenir à une version plus ancienne après migration :
  utiliser la sauvegarde JSON si besoin (elle se restaure dans toutes les versions).

TESTS : avec Node.js installé, lancer dans ce dossier :  node tests/run.js
  Ils exécutent le vrai code de l'app (exports PDF/Word/Excel, hors-ligne, sauvegarde, mot de passe, contrastes...).

GESTION (v23) : créer ses propres procédures
  Gestion > Procédures > « + Nouvelle procédure » : partir de zéro, du modèle standard, ou copier une procédure existante.
  L'éditeur (plein écran) : titre, description, catégorie, statut (Publiée / Brouillon), documents de référence, puis les étapes :
  titre, consigne, avertissement, points de contrôle (ajout / retrait un par un), options (sous tension, couple, relevé),
  documents par étape, ordre (↑ ↓), duplication, suppression. Une procédure publiée est disponible tout de suite.
  Gestion > Catégories : créer, renommer, supprimer les catégories de procédures et de documents (aussi créables à la volée
  depuis l'éditeur). L'écran d'accueil range les procédures par catégorie.
  Documents : la fiche du document permet de cocher les procédures où il doit apparaître ; il est aussi visible pendant la
  maintenance via le bouton « Tous les documents » et se met à jour en direct, même pour une maintenance en pause.

MENU ET CORRECTIONS (v24)
  Menu : sur téléphone, le bouton « ☰ Menu » remplace les boutons Gestion / Admin (qui débordaient de l'écran). Il donne un accès direct à
  l'accueil, à chaque section de Gestion autorisée (Clients & données, Procédures, Documents, Catégories, Planning, Droits & accès) et au mode
  administrateur. Sur tablette / ordinateur, les boutons habituels restent affichés. Les onglets de Gestion passent à la ligne : plus aucun n'est caché.
  Assistant : en passant à l'étape suivante, l'écran revient en haut (il restait décalé vers le bas).
  Planning : relancer une intervention déjà commencée reprend la maintenance en pause (plus de doublon) ; le droit « supprimer une intervention »
  donne bien accès à Gestion ; un utilisateur ne peut reprogrammer que la date et l'heure ; au-delà de 8 interventions, « Voir tout » les affiche.
  Rapports : un rapport supprimé ne peut plus être exporté à la place d'un autre, et l'intervention liée ne le référence plus.
  Clients : supprimer un client retire ses interventions à venir (la confirmation annonce leur nombre) ; restaurer une sauvegarde rattache
  les rapports au bon client.
  Procédures / documents : copies avec titres distincts (« … (copie 2) ») ; supprimer un document le retire de toutes les procédures et étapes ;
  les procédures supprimées ne réapparaissent plus au démarrage ; le droit sur les catégories est propre à chaque type (procédures / documents).

MOT DE PASSE OUBLIÉ (par e-mail)
  FONCTIONNEMENT
    1. Une fois (tant que tu as le mot de passe) : connecté administrateur, Gestion > Droits & accès (ou Données) > « E-mails de récupération ».
       Jusqu'à 5 adresses (Gmail, Outlook, pro...). Pour chaque ajout, un code est envoyé à l'adresse pour la VÉRIFIER : elle n'est enregistrée
       que si tu saisis ce code. Bouton « Retirer » pour en supprimer une (avec confirmation) ; pour modifier une adresse : ajouter la nouvelle, retirer l'ancienne.
       Un rappel s'affiche à la connexion tant qu'aucune adresse n'est enregistrée.
    2. Mot de passe oublié : écran « Accès administrateur » > « Mot de passe oublié ? » > on saisit son adresse e-mail > si elle est identique à l'une de
       celles enregistrées, un code à 8 chiffres est envoyé à cette adresse seulement (pas aux autres) > on saisit le code + un nouveau mot de passe (6 caractères minimum).
    SÉCURITÉ : si l'adresse saisie est DIFFÉRENTE de toutes celles enregistrées, aucun mail ne part, mais l'écran et les messages sont exactement les mêmes
    (un faux code est créé). Un curieux ne peut donc ni recevoir de code, ni deviner les adresses enregistrées.
    « Compte Google » : utilise simplement ton adresse Gmail comme adresse de récupération. La connexion « Se connecter avec Google » n'est pas utilisée :
    elle exige un projet Google Cloud et est souvent bloquée dans les applications APK (WebView).
  ENVOI (l'app n'a pas de serveur) : service gratuit EmailJS, internet nécessaire UNIQUEMENT pour l'envoi d'un code. Activation, une seule fois (~5 min) :
    1. Compte sur emailjs.com > « Email Services » > connecter la boîte mail qui ENVOIE (Gmail, Outlook...) > noter le Service ID.
    2. « Email Templates » > nouveau modèle. Champ « To Email » : écrire exactement  {{to_email}}  (l'app y met une adresse enregistrée, jamais celle tapée par un inconnu).
       Objet et texte, par exemple :
       « Code R.L ENERGIE : {{code}} — valable {{minutes}} minutes. Si vous n'êtes pas à l'origine de cette demande, ignorez ce message. »
       Noter le Template ID.
    3. « Account » > copier la Public Key. Dans « Security » : autoriser les appels depuis les navigateurs, et si tu publies sur GitHub Pages,
       limiter aux domaines autorisés à ton adresse github.io (empêche d'autres sites d'utiliser ta clé).
    4. Ouvrir js/config.js : service, template et key (Public Key) sont DÉJÀ renseignés dans cette version. Ne JAMAIS y mettre la Private Key. Puis changer V dans sw.js (rl-v24h -> rl-v25), sinon l'app garde l'ancien config.js en cache. APK : refaire l'APK avec les fichiers modifiés.
    5. Tester : Gestion > E-mails de récupération > ajouter ta propre adresse (un code de vérification est envoyé), puis « Mot de passe oublié ? » sur l'écran admin.
       APK : si l'envoi échoue avec « refusé par EmailJS (403) », EmailJS bloque par défaut les appels « non-navigateur » : activer l'option correspondante dans
       EmailJS > Account > Security, puis réessayer. Les autres refus (400 / 404) signifient presque toujours un Service ID, Template ID ou Public Key erroné.
       Variables envoyées au modèle (v24g) : {{to_email}} {{code}} {{passcode}} (= le même code) {{minutes}} {{time}} (heure limite, ex. 14:32) {{app}}. Le modèle peut donc utiliser {{passcode}} ou {{code}}.
       Depuis v24f, le message d'erreur reprend le code et la réponse d'EmailJS entre parenthèses, p. ex. « (EmailJS 422 : The recipients address is empty) » = le champ « To Email » du modèle doit contenir {{to_email}} ; 412 = compte Gmail/Outlook à reconnecter dans Email Services ; 400/404 = identifiant erroné.
       Quota : le plan gratuit d'EmailJS est limité en nombre d'e-mails par mois (vérifier sur emailjs.com/pricing) ; l'app limite déjà à 3 codes par heure.
  PROTECTIONS : code aléatoire (crypto), jamais stocké en clair, valable 10 min, utilisable une seule fois, 5 essais puis annulé, 60 s entre deux
  demandes, 3 demandes par heure maximum (compteurs conservés même si on recharge la page), un nouveau code annule le précédent, un code de
  vérification d'adresse ne peut pas servir à changer le mot de passe. Les adresses de récupération restent sur la tablette (elle n'est pas dans les sauvegardes JSON).
  SMS : non pris en charge. Envoyer un SMS exige un service payant et un serveur qui garde la clé secrète ; une app sans serveur ne peut pas le faire sans exposer cette clé.
  LIMITE À CONNAÎTRE : le mot de passe est vérifié sur la tablette elle-même. Ce dispositif empêche un utilisateur normal de s'octroyer l'accès admin,
  mais ne protège pas contre quelqu'un qui maîtrise les outils développeur du navigateur sur la tablette.
  Si js/config.js est laissé vide, le lien affiche seulement que la fonction n'est pas activée.

MESSAGES D'ERREUR / CONFIRMATION (v24b)
  Un même message n'est jamais affiché deux fois en même temps : si on clique à répétition sur un bouton, le message reste affiché (une seule fois,
  sa durée est prolongée et il fait un petit rebond). 3 messages différents au maximum à l'écran à la fois. Valable pour TOUS les messages de l'app.
